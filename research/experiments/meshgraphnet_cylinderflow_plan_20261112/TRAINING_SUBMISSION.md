# CylinderFlow · one-job MeshGraphNet training plan

The November 13 submission uses the existing POLUS P100 environment and the `normal` queue. Request one P100, four CPU slots on one exclusive host, 8 GiB host RAM and `-W 180`. C2, C3 and C4 have previously run this P100 stack. CPU affinity is `0,8,16,24`, with PyTorch interop set to one. The worker starts its deadline clock before activation and reserves the final three minutes for saving and shutdown.

Use seed 101, FP32, the two-output MeshGraphNet with 15 independent width-128 processors and two hidden layers per MLP, and Adam with two sampled train trajectories per batch. Run 1000 normalization-only batches before optimizer updates. Sample two distinct official train trajectories uniformly per batch and a uniformly sampled adjacent frame pair from each. The initial learning rate is 0.0001 and decays exponentially toward 0.000001, with factor 0.1 per five million updates applied to the difference from the floor. Add 0.02 training noise to NORMAL nodes, with reference gamma one. Use only the checksum-verified official train and validation TFRecords.

Validate before the first optimizer update and every 1000 updates on 16 fixed validation trajectories selected by a seed-101 shuffle of official record ordinals. Roll out from raw frames 100 and 300 for 100 steps. Report endpoint MSE at 1, 20 and 100, mean trajectory MSE, finite windows and persistence MSE at 100. Select the lowest validation E100 among checkpoints whose windows are all finite, keeping the earlier checkpoint on ties. The job stops at 100,000 updates or the internal cutoff, whichever comes first. The cap is not a throughput promise. At the technical throughput of 0.163 s per update alone, 100,000 updates would take over 4.5 hours. Random training I/O and validation add cost.

Write `latest.pt` atomically on startup, every 13 minutes of active runtime, after each validation and on graceful stop. Save before or during validation when needed to protect the checkpoint interval. The initial validation admission budget is 180 seconds, increased if measured validation takes longer than anticipated. Skip validation when the predicted duration exceeds time remaining before the cutoff, and interrupt an in-progress sweep between windows if it reaches the cutoff. Partial validation does not participate in best-model selection. The latest checkpoint includes model, optimizer, normalization buffers, Python and CPU/CUDA Torch RNG, sampler RNG, warmup and optimizer counts, validation selection state, configuration and dataset identity. Save the best eligible model separately as `best.pt`. No test split is staged.

Run artifacts are under `$HOME/gnn-p100-20261110/meshgraphnet-cylinderflow-training-20261113/`. LSF writes `lsf.<jobid>.out` and `lsf.<jobid>.err`. The worker writes `run.<jobid>/events.jsonl`, `config.json`, `latest.pt`, and `best.pt` after the first eligible validation. The submission directory preserves INTENT, the original response and ACCEPTED with the job ID. Use this run’s learning curves, validation quality, throughput and memory to decide on scaling. Six independent single-GPU runs increase the number of runs completed per batch. Training one model across six GPUs requires a compatible distributed PyTorch build and a tested implementation across hosts. The current POLUS build has distributed support and NCCL disabled.

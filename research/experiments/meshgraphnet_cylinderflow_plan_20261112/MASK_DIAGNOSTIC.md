# CylinderFlow · диагностика ранжирования масок

Фиксируем checkpoint 47 000 Adam updates из LSF 1618479. SHA256 `d4a3360760f191d4b05ee80111a32067f33aea5609466b12328b4e802b2a1386`. Тензорный SHA256 `ba1b9d7bc024205428be3ad6f60d23e9034e21f421d00ddb0c7c5b6a03332b08`. Исходник обучения `78d46a96214bb319872902859ffef828c400393f`. База исходников диагностики `3bd282102083a78e6521f4d180773d9bee4a9081`. Точные скрипты запуска закреплены в `source.sha256` перед отправкой.

Перемешиваем официальные ordinal 0–99 через `random.Random(101).shuffle`. Первые 16 ID оставляем для исходной оценки. Следующие восемь диагностических ID — **87, 19, 72, 15, 18, 80, 79, 88**. Следующие восемь — **58, 12, 49, 61, 82, 90, 5, 53** для будущего выбора каналов. Проверяем непересечение всех трёх групп. Два диагностических окна на траекторию начинаются с кадров 100 и 300. Test закрыт. Validation TFRecord проверяется по MD5 `0a2f5f59112d6aeb7fb42ef974daca4d`.

Считаем L2-норму входящей строки второго Linear вместе с bias и умножаем на L2-норму исходящего столбца следующего Linear. Ранжируем по возрастанию оценки в CPU float64, при равенстве по исходному ID канала. Трети содержат 43, 43 и 42 канала. По восемь масок на треть, один Python RNG с seed 101, порядок блоков 0–14, внутри edge затем node. Выбираем четыре ID без возвращения в каждом MLP, отбрасываем дубликаты целой маски. Каждый вариант независимо строится от исходных весов. Ширины 124 в 30 внутренних слоях, параметров 2 302 090 вместо 2 332 930, удалено 30 840 (1,322%). Выходы блоков сохраняют ширину 128. Проверяем буферы нормализации, неизменность плотного checkpoint, физическую проекцию против зануления активаций (FP32 atol 1e-5, rtol 1e-4) и строгую перезагрузку каждой сжатой модели.

Модель получает начальное эталонное поле и дальше подаёт предыдущий прогноз. Сохраняем покадровую MSE на активных узлах и по двум компонентам. Анализ строит E1/E5/E20/E50/E100 и средние по шагам 1–5, 1–20, 1–100. Окна усредняются внутри траектории, затем траектории имеют равный вес. Для сравнения используем неизменную начальную скорость и парные изменения от dense. Строгую инверсию считаем только если обе разницы превышают `1e-9 + 1e-4 * max(abs(a), abs(b))`. Spearman использует средние ранги при точных равенствах. Интервалы строятся из 10 000 bootstrap-выборок целых траекторий с сохранением всех масок и обоих окон, seed 101. Анализ показывает всю библиотеку и отдельно каждую треть. Неполные варианты остаются в таблицах со статусами. Для кривых берём одну полную маску ближе всего к медиане E100 в каждой трети, при равенстве выбираем меньший ID.

На POLUS один процесс использует одну P100, четыре CPU-слота и 8 ГиБ памяти. Результаты записываются атомарно по окнам. Для возобновления из того же каталога launcher проверяет исходники и входы, а затем пропускает уже записанные окна, включая зарегистрированные нечисловые результаты. При сборе сверить `finish-<job>.json`, число неудачных окон и сохранённые квитанции.

Лимит LSF для диагностики — 90 минут в `normal`, внутреннее завершение на 85-й минуте между окнами. Оценка перед подачей — 2191 с (36,5 минуты) для 400 модельных окон по 100 шагов и 16 окон persistence. Использована измеренная стоимость задания 1618544 (70,96 с на 32 окна) с коэффициентом 2, дополнительно 24 × 12,36 с на подготовку масок по консервативному CPU-замеру и 120 с на запуск и запись. Максимальная диагностическая сетка содержит 11 824 направленных ребра против 11 874 в замере. Запас относительно 90 минут — около 59%. На POLUS прошла CPU-проверка одной физической маски на крупнейшей диагностической сетке, включая строгую перезагрузку и сравнение с занулением активаций. Локально прошли 6 целевых pytest, проверки всех 24 масок на игрушечной сетке и синтетический тест анализа с известными инверсиями и отказом. Полные GPU-проверки выполняются внутри диагностического задания.

После завершения можно собрать результаты и запустить анализ. Замените `$POLUS_SSH_TARGET` на согласованное SSH-назначение.

```bash
mkdir -p "$GNN_ARTIFACT_ROOT/meshgraphnet-mask-diagnostic-20261113/collected"
ssh -4 -B en0 "$POLUS_SSH_TARGET" \
  'cd "$HOME/gnn-p100-20261110/meshgraphnet-mask-diagnostic-20261113" && tar -czf - results submission source.sha256 preflight.json split-preflight.json masks-preflight.json lsf.*' \
  | tar -xzf - -C "$GNN_ARTIFACT_ROOT/meshgraphnet-mask-diagnostic-20261113/collected"
root="$GNN_ARTIFACT_ROOT/meshgraphnet-mask-diagnostic-20261113"
python scripts/analyze_cylinderflow_mask_diagnostic.py "$root/collected/results" "$root/analysis"
```

Файлы анализа — `windows.csv`, `trajectories.csv`, `masks.csv`, `rankings.json`, два scatter PNG/PDF, кривые ошибки PNG/PDF и `REPORT.md`. Сравнение трёх критериев оценивает предпосылку гипотезы. Преимущество одного метода отбора каналов требует отдельного эксперимента.

## Как подключиться и запустить первое условие

С Mac при действующем исключении Outline:

```bash
ssh -4 ${POLUS_SSH_TARGET}
```

Пользователь добавил на Mac маршрут `${POLUS_IPV4}` через `${LOCAL_GATEWAY_IPV4}`; VPN остаётся включённым. После перезагрузки, смены сети, шлюза или IP сервера маршрут нужно проверить и при необходимости восстановить. Постоянная автоматическая настройка маршрута этой сессией не создавалась.

На сервере:

```bash
source "$HOME/gnn-polus-20261023/activate-polus.sh"
cd "$HOME/gnn-polus-20261023"
cat logs/environment-ready.json
bash submit-pilot.sh
```

Последняя команда **начинает научный эксперимент**: одно условие `cora_gcn_l3_h32`, seed 101, семь методов, 4 CPU-слота, до трёх часов. Она приведена для ручного запуска и в этой сессии не выполнялась. Файл задания отказывается работать без успешной записи готовности окружения.

Очередь проверяется через `bjobs`. Результаты: `~/gnn-polus-20261023/results/pilot-cpu-101/seed_101/cora_gcn_l3_h32`; журналы: `logs/lsf/pilot-cpu.<jobid>.out/.err`. Время одного условия ещё не измерено, поэтому укладывание всего условия в лимит очереди пока не подтверждено.

Файл задания, проверка без запуска и наблюдение — в [LSF-PILOT.md](LSF-PILOT.md). Другие условия и научный протокол — в [GNN-POLUS.md](GNN-POLUS.md). ## Что находится на сервере

Все новые файлы — в отдельном каталоге:

```text
${POLUS_TASK_ROOT}
```

- `env/`: отдельное окружение, активация через `activate-polus.sh`.
- `repo/`: чистая копия исследования, commit `72293149d8fff186dd268789e7b8fea5848c9360`.
- `data/`: 24 raw-файла Planetoid для Cora/CiteSeer/PubMed и SHA256; обработку выполнит целевой PyG при ручном запуске.
- `results/pilot-cpu-101/prepared-configs/`: шесть внешних конфигураций и документы происхождения. Алгоритмы и гиперпараметры сохранены; адаптированы пути, имя запуска и устройство.
- `sources/pytorch-v2.0.1/`: исходники на commit `e9ebda29d87ce0916ab08c06ab26fd3766a870e5` с записанным исправлением VSX.
- `patches/`, `source-archives/`: исправления, закреплённые источники и контрольные суммы.
- `logs/`: доказательства установки, готовности и чистоты репозитория.
- `setup-evidence.tar.gz`: компактный снимок итоговых журналов.

Системное ПО, общее ML-окружение, пользовательские `wave-cpp17` и `proj` не менялись. Модуль Anaconda имеет проблему с передачей аргументов в activation hook, поэтому рабочий профиль использует напрямую `etc/profile.d/conda.sh`, временно отключая `nounset` при активации.

## Готовый пакет и воспроизведение

Wheel около 54 МиБ:

```text
~/gnn-polus-20261023/sources/pytorch-v2.0.1/dist/torch-2.0.1+polus.power8.1-cp310-cp310-linux_ppc64le.whl
```

SHA256:

```text
30660e31f8c88159461ea647b2f175bdd23e501cad19b3a464fb451ddec8b830
```

Локальная резервная копия сохранена в `${GNN_ARTIFACT_ROOT}/polus-environment-20261023/wheel/`, SHA256 проверен после SCP. Wheel рассчитан на CPython 3.10/linux-ppc64le и зависит от библиотек подготовленного окружения, включая OpenBLAS; его переносимость на другой хост без проверки библиотек и путей не подтверждена. Для восстановления использовать `conda-explicit-final.txt`, `pip-freeze-final.txt`, записанный wheel и рецепты рядом с этой инструкцией.

Исходники получены по закреплённым Git SHA; большие подмодули перенесены через codeload-архивы из-за зависавших Git pack-передач. Контрольные суммы — в `materialization-manifest.json`. Основные gitlink-ревизии проверены; необязательные вложенные зависимости отключённых компонентов для CPU-сборки не требуются.

PyTorch 2.0.1 на POWER8 потребовал backport [PR 98511](https://github.com/pytorch/pytorch/pull/98511) и [PR 109886](https://github.com/pytorch/pytorch/pull/109886), с адаптацией контекста и явным `<climits>`. Менялись четыре заголовка PyTorch. SHA256 итогового diff:

```text
5682c75cb1c101f8b8bab9ee2990fcbaa7486166f83d0480337966741e6e5afc
```

BFD ld 2.39 не смог слинковать `libtorch_cpu.so` из-за переполнения `R_PPC64_REL24`; настройка оптимизации и размера групп отдельно не помогла. Проверенный вариант: `-fuse-ld=gold -Wl,--stub-group-size=1000000`. Полный итоговый рецепт — `build-torch-cpu.sh`; он разрешает только записанный diff исходников. Промежуточные неудачные задания и их зависимые проверки завершены или отменены.

## GPU и ограничения проверки

На frontend подтверждены две P100 по 16 ГБ, драйвер 440.33.01 и CUDA Toolkit 10.2. **GPU-окружение не настроено.** Выбранный PyTorch 2.0.1 требует CUDA ≥11.0 в [своём CMake-коде](https://github.com/pytorch/pytorch/blob/v2.0.1/cmake/public/cuda.cmake). Для P100 нужен отдельный согласованный набор пользовательских библиотек и драйвера либо обоснованная совместимость с более старым PyTorch. Системный стек этой сессией не менялся.

Singularity 2.6.1-dist слишком стар, чтобы считать прежние общие команды получения современного SIF проверенными. Готовые IBM WML CE с PyTorch 1.2/1.3.1 не соответствуют объявленным зависимостям проекта. CPU-путь сохраняет Python ≥3.10, torch ≥2.0 и PyG ≥2.4.

`normal` допускает пакетные задания до 180 минут и запрещает интерактивные. Команда `bsub -Is -q normal` для этой установки неприменима. Доступ к `extended`/`gpulong` ограничен; текущая учётная запись в их списках не обнаружена.

Импорты и конфигурации не доказывают успешное выполнение всех семи методов, градиентов GraSP или полного пилота. Это проверит первый ручной эксперимент. Результаты Polus CPU сохранять отдельно от Kaggle/GPU; аппаратные времена между ними не объединять.

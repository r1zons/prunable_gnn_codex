# GPU-окружение POLUS и технические запуски · 10 ноября 2026

На POLUS создано отдельное окружение `~/gnn-p100-20261110/env` для Tesla P100.
Проверены CUDA, GCN и GraphSAGE с архивными checkpoint Cora, а также SNIP и
инференс на Flickr. Исходный код проекта закреплён на
`32bf91cab509b58d7619797683e502f425a6f6bf`.

| Компонент | Конфигурация |
|---|---|
| Узлы и GPU | POWER8 / ppc64le, P100-SXM2-16GB, `sm_60`. Сборка и парная проверка на C4 с RHEL 7.4 |
| Системный стек | NVIDIA 440.33.01, CUDA 10.2.89 |
| Python и PyG | Python 3.10.22, PyG 2.4.0 |
| PyTorch | `1.13.1+polus.cu102.power8`, исходник `49444c3e546bf240bed24a101e747422d1f8a0ee`, GCC 7.3.1, OpenBLAS и GNU gold |
| Возможности сборки | CUDA включена. cuDNN, NCCL и распределённый режим отключены |

Wheel установлен в копию исследовательского CPU-окружения. Для чтения
архивных checkpoint в ограниченный загрузчик перенесена обработка `BINFLOAT`
из PyTorch 2.0.1 с сохранением `weights_only=True`. Манифест проекта требует
`torch>=2.0`, поэтому проверенный запуск импортирует закреплённый снимок
исходников через `PYTHONPATH`.

## Проверки LSF

| Задание | Состояние | Результат |
|---|---|---|
| 1617692 | DONE | CUDA-ядро `sm_60` и cuBLAS на одной выделенной P100 |
| 1617693 | DONE | Сборка wheel, установка и импорт PyTorch/PyG |
| 1617702 | DONE | GPU-forward, SNIP, физическое удаление каналов и строгий reload для Cora GCN и GraphSAGE |
| 1617705 | DONE | CPU/P100 на одинаковых checkpoint Cora и Flickr |
| 1617706–1617709 | DONE | Масштабирование пакета Flickr на 1, 2, 4 и 6 P100 |

В парной проверке CPU использовал четыре закреплённых физических ядра,
обе стороны использовали одну сборку PyTorch. На Flickr GraphSAGE L4/H256
dense forward занял **2535,88 → 86,06 мс** (29,47×), SNIP с физическим удалением
**5718,84 → 345,91 мс** (16,53×). Пик выделенной памяти CUDA составил **2,39 ГиБ**
за всю проверку. В трёх сравнениях совпали маски, число параметров и
validation-предсказания. Времена приведены после прогрева, с синхронизацией CUDA.

Один пакет масштабирования содержит 48 технических прогонов Flickr с целями
30% и 50%. У каждого процесса своя P100 и четыре локальных CPU-ядра. В
576 измеренных прогонах при совпадающей цели совпали маски, число параметров,
validation-предсказания и accuracy.

|---:|---|---:|---:|
| 1 | C4 | 20,860 | 39,289 |

Для двух GPU журнал 1617707 и данные процессов подтвердили C4, два разных
PCI-адреса и непересекающиеся CPU-ядра. `span[hosts=1]` размещает CPU-задачи
на одном узле, а `-gpu num=2` запрашивает две карты на узел. Масштабирование
относится к пакету независимых запусков. [IBM LSF span](https://www.ibm.com/docs/en/spectrum-lsf/10.1.0?topic=strings-span-string) · [IBM LSF GPU](https://www.ibm.com/docs/en/spectrum-lsf/10.1.0?topic=o-gpu)

## Воспроизведение и артефакты

Внутри LSF-задания с выделенной GPU загрузите окружение.

```bash
source "$HOME/gnn-p100-20261110/activate-p100.sh"
```

В этом же каталоге на POLUS сохранены `build-gcc7.sh`, `patch-binfloat.py` и
`validate-lsf.sh`. Короткую проверку Cora можно повторить из входного узла.

```bash
cd "$HOME/gnn-p100-20261110"
bsub -q normal -m polus-c4-ib.bmc.hpc.cs.msu.ru -n 1 -x -W 10 -M 8192 \
  -R 'span[hosts=1] rusage[mem=8192]' -gpu 'num=1:mode=shared:j_exclusive=yes' \
  -o 'validate.%J.out' -e 'validate.%J.err' < validate-lsf.sh
```

Скрипты запуска Flickr находятся в каталогах замеров под корнем окружения.
Wheel и установленная правка проверяются по `wheel.sha256` и
`binfloat-overlay.sha256`.

Локальные квитанции, журналы, точные команды LSF и контрольные суммы находятся
под `${GNN_ARTIFACT_ROOT}` в следующих группах.

- `polus-p100-20261110/` — сборка, проверка CUDA и checkpoint Cora.
- `polus-gpu-cpu-benchmark-20261110-173022/` — парные CPU/P100 замеры.
- `polus-flickr-gpu-scale-20261110-174115/` — квитанции 1/2/4/6 GPU.
